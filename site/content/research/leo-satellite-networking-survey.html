01卫星网络近况：部署与技术态势

2025–2026 年最大的变化是：巨型星座从"论文里的理想拓扑"变成了"可被测量的真实系统"，而真实系统与学术界长期假设的规则星座差距显著。

1.1 真实星座 ≠ 理想星座（对仿真研究最关键的一条）

亚利桑那大学 2026 年 3 月的工作 Starlink Constellation: Deployment, Configuration, and Dynamics（arXiv:2603.25835）用 2019–2025 的 TLE + CelesTrak 交会报告做了迄今最系统的星座解剖，结论直接冲击了大量已有 LEO 网络研究的前提：

  • 部署重心持续下移到 500 km 以下，v2 Mini 已占约 5,800 颗，成为主力代际；
  • Shell 1 每轨道面 18 星、约 20° 相位间隔，但存在大量 twin/triad 备份簇（间距 0.9–5.2°），即"非规则卫星"；
  • 卫星运行寿命 4–6 年，日故障概率 0.0128%，运行阶段中位数 864 天；
  • 核心论断：实际部署显著偏离理想的完全对称 Walker 星座——而 Hypatia 等主流仿真器默认生成的正是理想 Walker 配置。
研究含义：如果你的路由/TE 论文只在理想 Walker +Grid ISL 上评估，审稿人（尤其 SIGCOMM/NSDI 系）越来越可能质疑其外部效度。用真实 TLE 驱动、并加入故障与机动扰动，正在从"加分项"变成"及格线"。

1.2 激光星间链路（ISL）与拓扑设计

ISL 已从概念走向规模化运营：SpaceX、Telesat Lightspeed、Kuiper 均在推进光学交叉链路，目标是减少落地站依赖、构建在轨网状网。学术侧的关注点已从"能不能建"转向：

  • 拓扑设计空间：+Grid 之外的非规则/跨壳层 ISL 匹配问题（见 APNet/LEO-NET 系列的 topology design 研究）；
  • 时变图（TVG）建模：拓扑随时间演化的最优化，例如 Time-Dependent Network Topology Optimization for LEO Satellite Constellations（arXiv:2501.13280）；
  • ISL 切换对传输层的影响：ISL 路径变化引发的 RTT 抖动直接影响 TCP，这也是 SIGCOMM'25 LeoCC 的出发点。

1.3 直连手机（D2C / NTN）成为独立热点

2025–2026 年，Direct-to-Cell 从产业新闻变成了有实测数据支撑的研究方向。代表性工作包括 SIGCOMM'25 的 Direct-to-Cell Satellite Network without Satellite Navigation（清华），以及基于众包测量的 Direct-to-Cell: A First Look into Starlink's D2D RAN（arXiv:2506.00283）与 A Variegated Look at Direct-to-Cell Satellites in the Wild（ACM 2025）。3GPP NTN 与 D2C 两条技术路线的对比分析亦已有专门综述（arXiv:2605.05843）。

1.4 中国星座：从"能发"到"成网"

  • 千帆（G60）星座：2026 年初约 108 颗在轨，年度目标 324 颗，长期规划约 1.4–1.5 万颗；运力瓶颈正由商业火箭补齐。
  • GW（国网）星座：2026 年持续发射低轨组批（如低轨 02 组、20 组），与千帆形成双轨并进。
  • 国内学术侧的组织形态也已成型：CNKI/《天地一体化信息网络》《航天电子技术》等有成体系的路由与移动性管理综述，2025 年《未来网络发展大会》发布了《卫星互联网承载网技术白皮书》。

3.2 关键发现：仿真器的保真度危机

2026 年 4 月的 An experimental evaluation of satellite constellation emulators（arXiv:2604.04498）系统评测了 StarryNet / OpenSN / Celestial 三家，结论相当尖锐，这是目前最容易撑起一篇好论文的空白：

核心结论："没有任何现有卫星星座仿真器能匹配真实测量"——因为客户端调度、大气条件等关键因素完全未被建模（对照基准为 WetLinks 真实数据集）。

具体问题：① 星座状态更新延迟随网络规模无界增长，常常直接打断仿真；② StarryNet 主线因 CLI 方式调用 Docker，启动时间比开发分支慢 10 倍；③ OpenSN 运行时计算星座状态，延迟从 5 秒膨胀到 55 秒。

作者给出的理想架构：无守护进程的容器运行时 + eBPF 网络仿真 + 星座状态并行预计算 + 异构卫星配置支持 + 可视化与地理边界框裁剪。

3.4 选型建议

  • 做路由算法 / 时延分析、要可复现基线 → Hypatia（审稿人认可度最高，几乎是必须跑的 baseline）；
  • 要跑真实协议栈（BGP/SRv6/TCP 实现、真实内核） → StarryNet（开发分支）或 OpenSN；规模再大用 NetSatBench 的分布式方案；
  • 要实时交互 / 大规模 + 应用层实验 → xeoverse 思路（Mininet + 预计算增量更新）；
  • 做在轨计算 / LEO Edge → Celestial（Firecracker microVM，资源最省）；
  • 资源汇总入口：jwwthu/Satellite-Open-Source（工具+数据集大全）与 liuwei-network/awesome-satellite-network（按 13 个主题分类的论文清单，含路由/测量/安全/平台）。

04分域路由专题

"分域路由"在文献中有多个名字：hierarchical routing、partition-based routing、segment/zone routing、area-based routing。其共同动机只有一个：万颗星规模下，全局最短路计算与链路状态泛洪都不可行。

4.1 为什么必须分域

  • 计算复杂度：N=10,000 的 Dijkstra 在星上算力下每个拓扑快照都是负担，而拓扑变化以秒级发生；
  • 控制开销：全网链路状态泛洪的收敛时间可能超过拓扑保持稳定的时间窗（"路由还没收敛，拓扑又变了"）；
  • 稳定性：全局重算导致路径频繁抖动，直接破坏上层 TCP/QUIC；
  • 故障域隔离：单点失效不应触发全网重算。

4.2 五条主要技术路线

路线代表工作分域依据核心机制关键结果
轨道条带 + IS-IS 层次 A Routing Architecture for Satellite Networks（Tony Li, IETF draft-li-arch-sat / RFC 9717） 相邻若干轨道面组成 stripe stripe = IS-IS L1 区域，stripe 间轨间链路构成 L2；Area Proxy 使每个 stripe 对 L2 只暴露一条 LSP；转发面用 SR-MPLS（node SID + area SID）；结合轨道可预测性预计算拓扑变更 1,000 stripe × 1,000 星 = 100 万卫星可扩展，且不需要任何新协议
地标骨架图 + 段路由 Landmark-Based Skeleton Graphs（arXiv:2411.19679） 按分区大小 R 划分区域，每区设虚拟地标 把全网抽象成"骨架图"，包沿地标间的轻量骨架路径转发，区内用多路径概率转发分散流量 算法复杂度与隧道路径数均降低 R²，骨架路径缩短 √R，更新开销降低 R²
聚类分段 + 边界星 Secure and Scalable Rerouting in LEO（arXiv:2509.10173, ETH Zürich / Oxford） k-medoids 聚类划分虚拟 segment 边界卫星作为路由枢纽，负责段间通信与故障信息传播；对比 source / neighbor / segment / global 四种感知范围 高故障率下比邻居级方案少 30% 丢包、少 80% 环路；全局感知虽好但开销不可用
地理分区 Hierarchical Load-Balanced Routing via Geographic Partitioning（Appl. Sci. 2025）；Geographic-based failure-tolerant routing（Adv. Space Res. 2025） 按地表经纬度网格划分 卫星位置映射到地理网格，路由决策基于"当前覆盖哪个格子"而非卫星 ID，天然规避拓扑变化 负载均衡与容错，无需维护随卫星移动而变的状态
稳定分层（运营视角） Stable Hierarchical Routing for Operational LEO Networks（MobiCom'24） 面向真实运营约束的层次划分 强调路由稳定性而非最优性——在可运营的层次结构下抑制路径抖动 分域路由从"算得快"转向"算得稳"的代表性转折

4.3 与之相关的工程实践

  • SRv6 在 LEO 的落地实验：NetSatBench（arXiv:2604.27854）用 OneWeb 类星座（588 星 + 5 网关 + 7 用户）做了 SRv6 案例研究，发现端到端协同切换策略远优于本地策略——网关侧与用户侧协同选星可把 RTT 从数百毫秒降到约 35 ms，关键在于最小化 ISL 跳数；同时 BBR 在 LEO 典型丢包下明显优于 Cubic。这是目前把"分段路由 + 分域切换"在真实协议栈上跑通的最完整公开实验。
  • 拓扑分区做遥测：APNet'25 的 Topology-Adaptive LEO Satellite Network Telemetry via Graph Isomorphism and Topology Partitioning 把分区思想用在了 INT 遥测上，说明"分域"这一原语的适用面正在从路由外溢到测量与运维。
  • 开源可参考的路由代码：Fede-Berga/satellite_routing、sat-robustness-simu/nssatroute、Zone-routing-protocol（ZRP 经典实现，可作分域路由的起点）。
一句话总结分域路由的当前共识：分域的划分依据正在从"卫星 ID / 轨道结构"转向"地理位置 + 运营稳定性"，而转发面正在收敛到段路由（SR-MPLS / SRv6）——因为它天然能表达"先到某个域、再到域内某点"的两级语义，且不需要中间节点维护每流状态。

06研究空白与选题建议

① 高保真仿真器本身就是好选题 推荐

arXiv:2604.04498 已经把"现有仿真器全部对不上真实测量"这句话说出口，并列出了理想架构（daemon-less 容器 + eBPF 数据面 + 并行预计算 + 异构卫星）。把这套架构真正实现出来，并用 WetLinks / 真实 TLE 校准，是一篇结构清晰、贡献明确的系统论文。

② 非规则星座上的分域路由 推荐

现有分域方案（stripe、地标、地理网格）几乎都隐含"规则 Walker"假设。而 arXiv:2603.25835 证明真实 Starlink 有 twin/triad 备份簇、多壳层、日均 264 次机动。在非规则 + 高机动星座上，域该怎么划、域边界怎么随机动迁移——这是一个尚无人系统回答的问题。

③ 分域粒度的自适应控制

地标方案的收益是 R² 量级，但 R 在所有文献里都是静态超参。R 应随流量分布、故障率、星上算力动态调整——把它建模成在线控制问题（甚至 RL），是一个开销小、故事完整的切入点。

④ 分域路由 × 传输层的联合设计

LeoCC（SIGCOMM'25）证明了 ISL 切换对 CC 的破坏，NetSatBench 证明了协同切换能把 RTT 从数百 ms 降到 35 ms。但域边界切换事件是否应该显式通知传输层（类似显式路径变更通知）？这是一个跨层的空白。

⑤ 分域路由的安全与对抗

ETH 的工作已经证明分段路由在故障下优于邻居级方案，但只考虑了随机/定向故障。如果攻击者专门打击边界卫星（域枢纽），分域架构的脆弱性可能高于扁平架构——这是 SpaceSec/NDSS 方向的明确空位。

⑥ 星地一体的域间路由

当前工作基本止步于星座内部。天基域与地面 AS 之间的域间路由（BGP 怎么和秒级变化的天基拓扑共处、地面 PoP 如何选择接入域）几乎没有系统性研究，而这恰恰是运营商最关心的问题。
