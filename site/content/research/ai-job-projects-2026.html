找工作项目调研：AI 应用/Agent + AI Infra

面向国内校招 · 应届/学生 · 调研日期 2026-07-26

目标：AI 应用 / Agent 开发 目标：AI Infra / 推理部署 市场：国内 阶段：学生 / 应届

结论先说

主攻 AI 应用/Agent，用一个「推理服务侧」项目搭桥到 Infra。两个方向的岗位量、学历门槛差别很大：应用/Agent 岗位多、本科可投；AI Infra 更偏硕博 + 硬 CS 基础（CUDA、分布式、框架源码）。应届同时全力打两条线基本做不到，但「应用主线 + 服务化/性能副线」是一份简历能同时被两类 HR 捞到的最优解。

只做 2 个有深度的项目，不要做 6 个 demo。大厂对应届的明确要求是「2–3 个有技术深度的项目」，而面试官只挖你最深的那一个。判断标准很简单：这个项目你能不能连续被追问 20 分钟不露怯。

项目里没有数字，等于没有项目。把「跑通了」升级成「召回率 65%→87%、P99 延迟降 40%、单请求成本降 3 倍」，是应届生和「另外 500 个也做了 RAG 的候选人」之间唯一的分水岭。

⏰ 时间提醒

今天是 7 月 26 日。国内大厂秋招提前批一般 7–8 月已经在跑，正式批 9 月前后启动；实习转正是更省力的入口（部分公司实习转正率超 50%）。所以下面给了两条路线：6 周冲刺版（赶今年秋招/提前批）和 12 周完整版（目标下一届或明年春招/暑期实习）。

推荐项目（按优先级）

P1 · 垂类多智能体「深度研究」系统

旗舰 · 应用主线 难度 ★★★★

选一个你有信息优势的垂类（比如医保政策、论文综述、招投标、财报），做一个能自主拆解问题 → 多源检索 → 交叉验证 → 产出带引用报告的系统。这是 2026 年最能体现「Agent 工程能力」的项目形态：单 Agent 已经不够看，主智能体调度 + 子智能体分工才是当下 JD 在问的东西。

技术栈LangGraph / DeepAgents
周期4–6 周
代码量3k–6k 行
适配岗位Agent 开发、AI 应用

必须做到（否则就是普通 demo）

  • 任务规划可回溯：把 plan / 子任务 / 工具调用全部落 trace，能在 UI 上重放一次研究过程（WebSocket 推实时进度）
  • 失败与降级：工具超时、检索为空、子 Agent 跑偏时的重试与兜底策略——面试官最爱问这个
  • 上下文工程：长任务下的记忆压缩、子 Agent 只拿必要上下文、token 预算控制（讲得出「为什么这样切」）
  • 自建评测集：50–200 条带标准答案的问题，跑出「引用准确率 / 事实错误率 / 平均耗时 / 单次成本」，并有 baseline（单 Agent + 朴素 RAG）对照

面试一定会追问

为什么用多 Agent 而不是一个长 prompt？成本涨了多少，效果涨了多少，这笔交易划算吗？

子 Agent 之间怎么传上下文？为什么不直接共享全量 history？

怎么判断一份研究报告「够好了」，停止条件是什么？

P2 · 生产级 RAG 知识问答（带评测闭环）

必做地基 难度 ★★★

RAG 提及频率仅次于 Python，不做等于缺一块。但「做了 RAG」不值钱，值钱的是你把它从 70 分调到 90 分的那条完整路径。所以这个项目的重点不是搭起来，而是每一步优化都有前后数字。

技术栈混合检索 + Rerank
周期3–4 周
数据真实脏文档（PDF/表格/扫描件）
适配岗位几乎所有 AI 应用岗

差异化的关键动作

  • 向量 + BM25 混合检索，再加 Rerank 模型；每加一层都记录召回率/准确率变化
  • 分块策略实验：固定长度 vs 递归切分 vs 语义切分 vs 父子块，拿数据说明为什么选它
  • 引用溯源 + 幻觉拦截：答案必须指回原文片段；答不出时明确拒答（拒答率也是指标）
  • 难场景专治：表格问答、跨文档对比、多跳问题、时效冲突（新旧版本文件谁优先）
  • 评测自动化：改一行代码就能跑全量回归，形成「离线评测 → 发现退化 → 修复」的闭环

面试一定会追问

你的评测集怎么来的？标注标准是什么？会不会过拟合到你自己的测试集？

Rerank 带来多少收益、多少延迟？线上你会不会开它？

用户问了一个知识库里没有答案的问题，系统的行为是什么？

P3 · 结构化数据 Agent（NL2SQL 智能问数）

替补 / 可换 P1 难度 ★★★

业务落地感最强的一类项目，国内企业需求很实在（电商问数、经营分析）。技术上把数仓、向量检索、字段值检索、工作流编排串成一条链路，比纯文本 RAG 更能体现工程能力。如果你更想去做 ToB / 业务中台方向，用它替代 P1。

技术栈MySQL + Qdrant + ES + LangGraph + FastAPI
周期3–4 周
难点Schema 召回、口径歧义
适配岗位AI 应用、数据智能

必须做到

  • Schema 检索：几百张表里选对表和字段（向量召回表结构 + ES 召回枚举值）
  • SQL 正确性保障：语法校验、执行前 dry-run、结果合理性检查、失败自修复循环
  • 指标口径消歧：「GMV」到底算不算退款？做一层业务指标字典而不是硬塞进 prompt
  • 指标：执行成功率、SQL 精确匹配率 / 结果一致率，分难度分级统计

P4 · LLM 推理服务网关（应用 ↔ Infra 的桥）

双投必备 难度 ★★★☆

这是整份方案的关键一环：它让同一份简历同时对应用岗和 Infra 岗成立。做一个自己的推理服务层——多模型路由、语义缓存、限流熔断、可观测、压测报告、成本核算。应用岗看到的是「你懂上线」，Infra 岗看到的是「你懂吞吐和延迟」。而且它不需要 8 卡集群，一张消费级显卡或租云卡按小时就能做。

技术栈vLLM/SGLang + FastAPI + Redis + Prometheus/Grafana
周期3–4 周
硬件单卡即可（可租）
适配岗位AI 应用 + AI Infra 双向

必须做到

  • 压测曲线：用 k6/locust 画出并发 → 吞吐(tokens/s) → P50/P99 延迟的关系曲线，找到饱和点
  • 调参实证：连续批处理参数、max_num_seqs、gpu_memory_utilization、前缀缓存开关各自带来多少吞吐变化
  • 量化对比：FP16 / INT8 / AWQ 或 GPTQ 的吞吐、显存、精度损失三维对照表
  • 语义缓存 + 限流：缓存命中率、成本下降幅度；令牌桶限流与优雅降级
  • 成本账：每千次请求的 GPU 成本，和直接调 API 对比，给出什么规模下自建划算

面试一定会追问

吞吐上不去时你怎么定位瓶颈是算力、显存带宽还是通信？（答不出 Roofline 会很吃亏）

PagedAttention 和 continuous batching 分别解决什么问题？

P99 延迟被长请求拖高，你怎么做请求调度？

P5 · mini-vLLM 复现 + 源码贡献

Infra 主线 难度 ★★★★★

如果真要打 AI Infra，这是绕不过去的一关。从零实现一个小型推理引擎（KV cache 分页管理 + 连续批处理 + 简单调度器），再去读 vLLM/SGLang 源码、写系列笔记、提几个能被 merge 的小 PR（文档、测试、小 bug、算子适配）。开源贡献记录是大厂 JD 明确列出的加分项，而且它是极少数能让本科生绕过学历筛的东西。

技术栈PyTorch + CUDA/Triton
周期6–10 周
产出代码 + 系列博客 + PR
适配岗位AI Infra、推理优化

分阶段做，别一口吃下

  • 第 1 步：朴素逐 token 生成 → 加静态批 → 加 continuous batching，记录吞吐提升倍数
  • 第 2 步：实现分页 KV cache（block 分配/回收/复用），对比显存碎片率
  • 第 3 步：手写一个融合算子（softmax / layernorm / 简版 FlashAttention），用 Nsight 或 PyTorch Profiler 出前后对比
  • 第 4 步：读 vLLM 调度器与 SGLang RadixAttention，写 5–8 篇源码笔记发出去（这本身就是 personal brand）
  • 第 5 步：从 good first issue 起提 PR，目标 merge 1–3 个

配套要背的高频考点

  • KV cache 管理：PagedAttention、前缀/Radix 复用、continuous batching
  • 量化：GPTQ / AWQ / SmoothQuant / FP8 的原理与精度损失控制
  • 投机解码；动态批 vs 静态批的吞吐-延迟权衡
  • 分布式训练基础：ZeRO 1/2/3、FSDP、Megatron 3D 并行、All-Reduce 通信
  • 手撕高频：Top-K/Beam Search 采样、LRU Cache、MoE Top-K 路由

P6 · Agent 评测 & 可观测性工具（差异化加分）

小而锋利 难度 ★★☆

几乎没有应届生做这个方向，但每家真正在做 Agent 落地的公司都缺人。做一个轻量的 evals + trace 工具：自动跑测试集、按维度打分（正确性/引用有效性/工具调用正确率/成本）、给 PR 出回归报告。可以对着 Langfuse 这类开源平台学架构，然后做成你自己项目 P1/P2 的质量门禁——三个项目就此串成一个体系，而不是三个孤立作品。

技术栈OpenTelemetry + LLM-as-judge
周期1.5–2 周
亮点候选人稀缺度高
适配岗位AI 应用、AI 平台/工程效能

做到这几点就够

  • trace 全链路（prompt / 工具调用 / token / 耗时 / 成本）落库可查
  • LLM-as-judge + 规则校验双轨评分，并且验证过 judge 与人工标注的一致性
  • CI 集成：效果掉超过阈值就红灯，附差异样本
  • 替代方案：做 3–5 个实用 MCP server + 一个自己的 host，展示对工具生态的理解

组合怎么选

只投应用 / Agent

P2（地基）+ P1（旗舰），有余力补 P6。简历上 P1 写 6–8 行，P2 写 4–5 行，P6 一行带过但面试时能展开。

双投（推荐你）

P2 + P4。P4 是桥：投应用岗时它叫「服务化与成本优化」，投 Infra 岗时它叫「推理性能调优」。同一个项目，两套讲法。

铁心冲 Infra

P5 + P4，且必须配「源码笔记 + 至少 1 个 merged PR」。同时把分布式训练那套八股补齐，否则一面就被问穿。

别做这些（同质化重灾区）

  • 套壳 chatbot——调个 API 加个前端，没有检索、没有评测、没有指标
  • 情感分析 / 文本分类——2018 年的项目，现在只证明你没跟上
  • 「在 HF 上微调了一个模型」——跑通 LoRA 脚本人人都会，没有数据构造和评测就没有信息量
  • 教程原样复刻——面试官见过同一个仓库十遍；至少换数据、换难场景、加上你自己的优化对比
  • 项目凑数量——5 个浅项目的说服力远低于 2 个能被追问 20 分钟的项目
  • 只有架构图没有数字——「效果不错」「性能有提升」这类表述会被直接判定为没做过

简历怎么写（四要素 + 正反例）

每个项目按 项目描述 → 个人工作 → 技术难点 → 收获 四段写。核心原则：面试官考察的是你怎么解决问题，不是你做了哪些操作。每一条都要能扛住追问。

✗ 项目描述 基于大模型的智能问答系统

✓ 项目描述 面向 10 万+ 员工的企业知识库问答系统，支持 3 万份制度文档的检索与溯源

✗ 个人工作 使用 LangChain 搭建了 RAG 流程

✓ 个人工作 设计向量 + BM25 混合检索并引入 Rerank，答案准确率从 72% 提升到 91%

✗ 技术难点 检索效果不太好

✓ 技术难点 长文档单块信息丢失导致召回差，改用递归切分 + 上下文窗口扩展，召回率 65%→87%

✗ 收获 学会了 LangChain 框架

✓ 收获 形成了一套 RAG 效果归因与优化的方法论，能定位问题出在切分、召回还是生成环节

数字从哪来（学生也能造出真指标）

  • 自建评测集：50–200 条问题 + 标准答案，自己标（标注标准写清楚，面试会问）。这是最重要的一步——没有评测集就没有一切数字
  • 永远留 baseline：朴素实现 vs 你的优化版，指标差值就是你的价值
  • 压测：k6 / locust 出并发-吞吐-延迟曲线，报 P50/P99 而不是平均值
  • 成本：每千次请求的 token 花费 / GPU 小时成本，优化前后对比
  • 消融实验：去掉 Rerank、去掉缓存、去掉多 Agent 分别掉多少，证明每个模块都不是摆设
  • 失败案例集：整理 10 个典型 bad case 和你的处理办法。面试时主动拿出来讲，可信度直接拉满

面试高频考点速查

应用 / Agent 向

  • Transformer 基础、Attention、位置编码
  • RAG 全链路：切分、embedding 选型、混合检索、Rerank、query 改写、多跳
  • 幻觉的成因与工程缓解手段
  • Agent：ReAct、Function Calling、工具选择错误怎么办、循环怎么终止
  • 多 Agent 协作模式与上下文传递
  • MCP 协议解决什么问题、和普通工具调用的区别
  • 上下文工程：长会话记忆、压缩、token 预算
  • Prompt 注入与越狱防护
  • 微调基础：LoRA/QLoRA、什么场景该微调而不是 RAG
  • 评测：怎么衡量一个 Agent 好不好

Infra / 推理向

  • KV cache、PagedAttention、前缀 / Radix 复用
  • continuous batching vs 静态批；吞吐与延迟权衡
  • Prefill / Decode 阶段特性差异与分离部署
  • 量化：GPTQ / AWQ / SmoothQuant / FP8
  • 投机解码原理与收益条件
  • FlashAttention 做了什么优化
  • Roofline 模型判断算力 / 带宽 / 通信瓶颈
  • 分布式：ZeRO 1/2/3、FSDP、Megatron 3D 并行、All-Reduce
  • MFU 指标、Nsight / PyTorch Profiler 用法
  • 系统设计：设计一个高 QPS LLM 服务（调度、扩缩容、成本）
  • 手撕：Top-K / Beam Search、LRU Cache、MoE Top-K 路由
